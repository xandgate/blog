Today is August 2, 2026. Two years after the EU AI Act entered into force, the obligations for high-risk AI systems — including human oversight, transparency, and audit trails — are now enforceable.

If you're running AI agents in production, this isn't a future problem anymore. It's a today problem.

## The compliance gap nobody talks about

Most "agent governance" today looks like this:

```
You are a helpful assistant. Before deploying to production, 
always ask for human approval.
```

That's a system prompt. It's a suggestion. It's not governance — it's a hope with a semicolon.

We proved this in our own dogfooding. We built a cooperative approval system where the agent calls an API before taking consequential actions. The agent skipped it. Not because it was malicious — because the LLM chose a different path through the tokens and the approval call never happened.

**Zero percent compliance.** With a working approval API, with the agent trained to use it, with the policy right there in the system prompt.

If your compliance strategy depends on the agent choosing to follow rules, you don't have a compliance strategy. You have a suggestion.

## What enforcement actually looks like

Real governance doesn't ask the agent for permission. It intercepts at the execution layer — the harness — where the agent has already made its decision and can't take it back.

Here's the chain:

1. **Agent decides** to call `terminal("git push origin main")`
2. **Harness receives** the tool call (the agent is done — it can't undo this)
3. **Plugin classifies** the action: `deployment, version_control` → risk: `high`
4. **Plugin checks policies**: match → mode: `hitl_gate`
5. **Harness blocks execution** and shows the approval prompt
6. **Human decides** → approved or denied
7. **Harness executes or blocks** accordingly

The agent never gets to step around this. Steps 2-5 happen inside the harness. The agent only controls step 1.

## The three-tier speed model

The obvious objection: "Won't this slow everything down?"

No. Most tool calls are low-risk and pass through instantly:

| Tier | What happens | Latency | When |
|------|-------------|---------|------|
| **Pass-through** | No policy match → execute | <5ms | `read_file`, `search`, `ls` |
| **Grace period** | Low-risk match → execute + notify | ~50ms | `write_file`, `mkdir` |
| **HITL gate** | High-risk → block until human decides | Human-dependent | `git push`, `rm -rf`, payments |

99%+ of agent actions hit pass-through. You forget the plugin is there — until it catches something that matters.

## Shadow mode: observe before you enforce

The hardest part of adding governance isn't the technology. It's the fear of breaking things.

Shadow mode solves this: install the plugin, classify and log every tool call, but **block nothing**. You get a week of real data showing what the classifier catches, what it misses, and what policies would have triggered. Then you flip to enforce with confidence.

Observe → Tune → Enforce. Zero risk until you're ready.

## What about privacy?

The obvious concern: if you're monitoring agent actions, are you sending everything to some cloud?

No. Classification happens locally — on your machine, in-process, zero API calls on the hot path. Only denied and high-risk tool calls feed the shared classifier. 99%+ of your agent's actions never leave your infrastructure.

Enterprise on-prem? Zero data egress. The shared classifier is optional, not required.

## What this can't catch

Honest gaps matter more than marketing spin:

If your agent runs `python refund.py`, the plugin sees the script name — not the Stripe API call inside it. Arbitrary code execution is opaque to any harness-level gate.

For those cases, you need **target-side enforcement**: Stripe fraud rules, IAM policies, API scopes. No harness-level governance tool can see inside arbitrary code execution. We'd rather lose a sale than pretend otherwise.

## The EU AI Act is real. Your governance should be too.

Article 14 of the EU AI Act requires that high-risk AI systems be designed so they can be "effectively overseen by natural persons during the period of use." Not advised. Not suggested. **Effectively overseen.**

A system prompt is not effective oversight. A cooperative API the agent can skip is not effective oversight. A plugin the agent cannot bypass — that's effective oversight.

If you're running agents in production, today is the day to stop hoping they follow the rules and start enforcing them.
